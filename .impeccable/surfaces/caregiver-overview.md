FORM: Code-led, local refinement of the established caregiver surface. A new concept roll or image comp is inapplicable to this bounded hierarchy and interaction change.

Intellectual activity is represented only by the existing per-topic observable counts with the required contextual header. No aggregate, concern sorting, causes, graph search or simulated-person Q&A.

INTERACTION: Topic rows expand into plain counts and fixed comparisons. The suggestion form opens inline, attributes exact text to Maya, keeps memory claims and suggested questions separate, accepts one optional local photo, and lists/removes her own local suggestions. No immediate call, notification, backend graph write or promotion into Susan's account. Existing source selection remains reachable. The prototype label and saved-state text make the local boundary explicit.

RESPONSIVE: Two desktop columns for overview and action; one continuous column on phone. Topic summaries wrap and expand vertically, with 44px+ controls. Theme and large-text settings remain supported. No new motion or imagery.

QUALITY BAR: A caregiver can explain what was discussed, what Susan chose to share, and what they can contribute after one viewport. Unknown feelings remain unknown. A large underlying graph never becomes a visualization burden. Verify desktop, phone and the actual browser viewport; finish review and documentation required.

LATEST USER STEER: The caregiver may now suggest a question for a future session. This explicitly changes the earlier family-question redirect-only requirement for this frontend preview. It is a request for Susan to answer in her own words, never permission to answer from the graph. Default to the next agreed call window while the optional timing preference is pending. Nothing bypasses patient choice or share-confirmation. The backend retains its existing contracts; integration requires a separately reviewed change.
